Each option, honestly

/logout + /login

Built into Claude Code. Run /logout, then /login, and sign in to the other account in your browser.

  • Good: nothing to install, nothing to configure.
  • Less good: one account at a time, and a browser sign-in on every switch. The claude-swap README also warns that current Claude Code may revoke the refresh token of the account you log out of, so going back means signing in again.
  • Claude Desktop works the same way: one account per app, switch by logging out and in. A feature request for multi-account support in the Mac app (anthropics/claude-code#32783) describes exactly that.

Pick it if you switch rarely.

CLAUDE_CONFIG_DIR shell aliases

Claude Code reads its config, and its login, from the folder in CLAUDE_CONFIG_DIR. Give every account its own folder and an alias:

alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
alias claude-personal='CLAUDE_CONFIG_DIR=~/.claude-personal claude'
  • Good: free, no extra tool, and every account can run at the same time in its own terminal. You sign in once per folder.
  • Less good: each folder starts empty, so skills, settings and CLAUDE.md are separate unless you symlink them from ~/.claude. Nothing tells you which folder holds which account. Claude Desktop is not covered.

This is the mechanism under every other multi-account option here, including ours. Our free, open source claude-switch CLI wraps it, with the shared folders symlinked for you, on macOS and Linux.

Pick it if you only use Claude Code in a terminal and like owning your setup.

claude-swap

A free, open source command line tool (realiti4/claude-swap) that stores the login of each account and swaps the active one with cswap switch.

  • Good: a usage dashboard with 5-hour and 7-day limits for every account, automatic switching before you hit a limit, a session mode (cswap run) for accounts side by side, an optional menu bar, and it covers the VS Code extension. Runs on macOS, Linux and Windows.
  • Less good: a swap changes the account for every Claude Code using your default login. On macOS a running session picks it up once the Keychain cache expires, about 30 seconds per the README, or right away after a restart. It needs Python 3.12+, and Claude Desktop is not covered.

Pick it if you rotate accounts to stretch rate limits, or work on Linux or Windows.

Claude Switch (Switch for Claude)

A Mac app that gives every account its own profile. A profile opens Claude Desktop in its own window with its own login, and Claude Code in Terminal, iTerm, Ghostty or Warp, signed in to the same account.

  • Good: Claude Desktop and Claude Code in one place, all accounts open at once, email and plan shown per profile, every profile one click away in the menu bar. Skills, settings and CLAUDE.md stay shared. It finds profiles you already made with Multi-Claude, Multiple Claude or the claude-switch CLI and opens them where they are. No account, no analytics, logins stay in your macOS Keychain.
  • Less good: Mac only, and it costs $9.99 once. It shows no usage numbers and doesn't switch for you near a rate limit. Under the hood it uses the same folders as the alias route, so if you only live in a terminal, an alias does the Claude Code part for free.

Pick it if you use Claude Desktop, or want all your accounts a click away without shell setup.

Questions

Can Claude Code be signed in to two accounts at the same time?

Not in one config folder. Claude Code keeps one login per config folder, so running two accounts at once means one config folder per account, set with the CLAUDE_CONFIG_DIR environment variable. Shell aliases, claude-swap's session mode and Claude Switch all build on that.

Is there a free way to switch Claude Code accounts?

Yes. /logout and /login are built in, a CLAUDE_CONFIG_DIR alias is one line in your shell config, and claude-swap and the claude-switch CLI are free and open source.

What about Claude Desktop?

Claude Desktop keeps one account per data folder. To switch in the app you log out and back in. Claude Switch opens Claude Desktop with a separate data folder per profile, so several accounts can be open in their own windows at once. claude-swap and CLAUDE_CONFIG_DIR aliases cover Claude Code only.

Do I have to restart Claude Code after switching?

With separate config folders there is nothing to restart: each terminal runs its own account. With claude-swap's switch command, the README says a running session on macOS picks up the new account once Claude Code's Keychain cache expires, after about 30 seconds, and a restart applies it at once.
